# 第2段階 実装報告

対象：認証、利用者の役割と権限、基本画面、顧客台帳、写真の撮影・アップロード
（設計：[01-requirements.md](01-requirements.md) 〜 [05-security.md](05-security.md)）

## 1. 確認した方法と結果

| 確認 | 結果 | 内容 |
| --- | --- | --- |
| RLS・権限のテスト（`npm run test:rls`） | ✅ 94項目すべて成功 | 素の PostgreSQL 16 に Supabase の認証・保存場所の最小限の再現を用意し、実際のマイグレーションを適用して、3つの役割と未ログインで確認 |
| 単体テスト（`npm test`） | ✅ 30項目すべて成功 | 撮影品質の判定、顔の向きの推定、役割と URL の対応、外部サイトへの転送防止、入力検証、CSP |
| 型チェック・ESLint | ✅ エラーなし | |
| 本番ビルド（`npm run build`） | ✅ 成功 | |
| ブラウザでの動作確認（Playwright + Chromium、Supabase 未接続） | ✅ | 公開画面の表示、入力エラーの表示、未ログイン時の振り分け、セキュリティヘッダー、CSP の下での顔検出（MediaPipe）の読み込み、疑似カメラでの撮影 → 撮り直し → 確認画面、画像以外のファイルを選んだときのエラー表示 |

RLS のテストで確認した主な点：

- 一般ユーザーは、他人のプロフィール・写真・撮影セッション・同意を読めず、消せない
- 一般ユーザーは自分の役割・有効状態を変えられず、顧客台帳・監査ログにアクセスできない
- スタッフは担当の顧客だけを見られ、担当外の顧客の写真ファイルにもアクセスできない
- スタッフ・管理者も、一般ユーザーのセルフ撮影の写真は見られない
- 撮影と保存の同意がないと撮影セッションを作れない。同意を撤回すると新しい撮影はできない
- 写真ファイルは決まった場所（`self/本人ID/…` または `salon/顧客ID/…`）以外に保存できない
- 停止されたスタッフは、ログイン中でもすぐに何も見られなくなる
- 監査ログは管理者も含めて誰も変更・削除できず、操作した人は自動で記録される

## 2. 完成した機能

| 区分 | 機能 |
| --- | --- |
| 認証 | 新規登録（18歳以上の確認・規約への同意・メール確認）、ログイン、ログアウト、パスワード再設定、スタッフの招待とパスワード設定 |
| 権限 | 3つの役割（一般ユーザー／スタッフ／管理者）。画面の振り分け（proxy）・サーバー処理での確認・データベースの RLS の3段階 |

| 一般ユーザー | ホーム、撮影、写真、設定（表示名、同意の確認・撤回） |
| サロン | ダッシュボード、顧客台帳（検索・並び替え・ページ送り）、顧客の登録・編集、顧客ごとの写真・同意、顧客の撮影 |
| 管理者 | 管理トップ（人数・件数）、スタッフの招待・役割変更・停止、担当の割当・解除、全顧客の一覧・削除、監査ログの閲覧 |
| 共通 | セキュリティヘッダー（CSP〔nonce 方式〕・HSTS など）、個人情報を含む画面のキャッシュ禁止、エラー画面、ホーム画面に追加するための manifest・アイコン |

## 5. 設計からの変更点

- Next.js 16 では `middleware.ts` が `proxy.ts` に名前が変わったため、`src/proxy.ts` に実装した。
- 写真の保存場所の決まりを、データベースの関数（`photo_storage_path`）で一元化し、写真の情報の登録と Storage の両方の RLS で同じ関数を使うようにした。
- 顧客の登録は、登録と担当の割当を同時に行うため関数（`create_customer`）経由に限定した。
- 役割・有効状態の変更は関数（`admin_update_member`）経由に限定し、管理者が自分自身の権限を外せないようにした。
