### テスト環境についての注意（必ずお読みください）

- データベースのテストは、Supabase と同じ PostgreSQL に **本番と同じマイグレーションファイル** を適用し、
  Supabase の役割（`anon`・`authenticated`）と `auth.uid()` を再現した環境で実行しています。
- 画面の自動テスト（E2E）は、開発環境で Docker（本物の Supabase をローカルで動かす仕組み）が使えなかったため、
  **Supabase の API を再現したテスト用サーバー**（`scripts/e2e/fake-supabase.mjs`）を使っています。
  データベース・RLS・関数は本物の PostgreSQL で動いていますが、Supabase のサーバーそのものではありません。
- **本物の Supabase・Vercel 上での動作確認はまだ行っていません。** 公開時に `docs/setup.md` の 7. の確認項目を実施してください。
- 実機のスマートフォンでの確認は行っていません（Playwright の Pixel 7 相当の画面サイズ・タッチ操作で確認）。
  公開後に、店舗のスマートフォン（iPhone・Android）で予約を1件試してください。


## テストの実行方法

```bash
cd booking-app
npm install
npm run lint && npm run typecheck && npm test   # 静的チェックと単体テスト
npm run test:db                                 # PostgreSQL 15 以上の initdb / pg_ctl / psql が必要
npm run build && npm run test:e2e               # 上記に加えて Playwright の Chromium が必要
```
